# Design Brief Template

Use this template to define the experience design problem before wireframes, mockups, or implementation.

## 1. Product / Feature

```text

Feature or surface:
Product area:
Status: draft | review | approved | superseded
```

## 2. User Problem

What user problem does this design solve?

## 3. Target User

Who is the primary user and what are they trying to accomplish?

## 4. Product Intent Alignment

Reference the product intent or blueprint this design supports.

```text

Non-goals:
```

## 5. Scope

What is included and excluded?

```text
Included:
Excluded:
Assumptions:
Open questions:
```

## 6. User Flow Summary

```text
Entry point -> Step 1 -> Step 2 -> Output -> Review/next action
```


## 9. Constraints

Examples:

```text
- Must reuse existing app shell/navigation.
- Must follow product design system.
- Must preserve existing feature groups.
- Must be usable on target viewport sizes.
- Must not introduce new dependencies without approval.
```

## 10. Design Fidelity Needed

Choose one:

```text
sketch
wireframe
mockup
implementation-ready interaction contract
```

## 11. Review Criteria

- [ ] Solves the stated user problem.
- [ ] Supports product intent.
- [ ] Clear primary action.
- [ ] Covers required states.
- [ ] Does not conflict with existing navigation or product shell.
- [ ] Ready to turn into engineering contract.
